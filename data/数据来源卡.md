## 三、字段结构【本地实测】

21 列 = 1 个 ID + 1 段原文 + 1 个星级 + **18 个维度标注列**。

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | 整数 | 评论编号，材料里所有引用（如 #1376、#24104）都可凭此在 CSV 中定位 |
| `review` | 文本 | 评论原文，中文，长度不均，含口语与错别字 |
| `star` | 浮点 | 星级 1.0–5.0 |

18 个标注列（顺序与数据集一致）：

```
Location#Transportation   Location#Downtown      Location#Easy_to_find
Service#Queue             Service#Hospitality    Service#Parking
Service#Timely            Price#Level            Price#Cost_effective
Price#Discount            Ambience#Decoration    Ambience#Noise
Ambience#Space            Ambience#Sanitary      Food#Portion
Food#Taste                Food#Appearance        Food#Recommend
```

## 四、标注取值域【本地实测】

| 取值 | 含义 |
|---|---|
| `1` | 正向提及 |
| `0` | 中性提及 |
| `-1` | 负向提及 |
| `-2` | **未提及**（该评论没有谈到这一维） |

> `-2` 是这份数据最关键的设计。没有它，分母会被算错——把"没提到"当成"中性"或"没问题"，正是商家看评论时最常见的错误。引擎的 `audit` 里，`gold_men = {k for k, v in gold.items() if v != -2}` 这一行就是按这个口径写的。

## 五、标注怎么来的【论文声明】

由数据集作者组织的标注员人工逐维标注（每条评论的每一维独立给 1/0/-1/-2）。标注员与引擎无任何关系——这一点决定了 `audit` 的结果不是自测。

标注员人数、一致性检验（如 Kappa 值）**【待核】**，材料里未引用，需要时按论文原文补。

## 六、我们用它做什么、不做什么

| 用途 | 说明 |
|---|---|
| ✅ 用 | 作为**公开基准**验证引擎的极性判断与维度识别能力（`audit` 子命令，结果 0.729 / 0.725 / 0.739） |
| ✅ 用 | 作为**方法演示**的样本源，让材料里每个比例、每句原话都能复跑 |
| ❌ 不用 | 不作为任何**单店**的经营结论。这是跨店跨城的公开基准集，不能代表某一家的真实经营状况 |
| ❌ 不用 | 不对外宣称"分析了某品牌/某城市的真实经营数据" |

> 答辩口径：**"这是 32 城公开基准集（城市数待核），不是单店数据，结论用于方法演示。"** 这句必须说在前面，否则会被追着问"你这是哪家店的数据"。
